# 软件定义工业互联网流量管控模拟器 (SIFA Simulator)

## 1. 项目简介

本系统是一款面向工业互联网场景的流量管控模拟器，旨在实现软件定义网络（SDN）架构下的确定性网络传输。系统通过集成 **遗传算法 (GA)** 进行路径规划、**多维特征分类器 (PLSAFC)** 进行业务流量识别，以及 **粒子群优化 (PSO)** 进行确定性资源编排，解决了工业场景下控制类流量对时延和抖动极其敏感的问题。

## 2. 核心技术栈

- **开发语言**: Python 3.10+
- **GUI 框架**: PyQt6 (实现高度交互的控制台与监控面板)
- **数据可视化**: PyQtGraph (高性能实时拓扑渲染、路径高亮及流量动画)
- **数学与算法库**: NumPy (用于 PSO 粒子的向量化计算与 GNN 特征处理)
- **预测模型接口**: 支持 ONNX Runtime / PyTorch (集成 GNN 图神经网络性能预测器)
- **架构模式**: 观察者模式 (Engine Callbacks 机制实现逻辑与 UI 解耦)

## 3. 核心算法逻辑

### 3.1 遗传算法 (GA) 路径部署

- **目标**: 在全连通网络中寻找满足服务链（SFC）能力需求的最佳节点路径。
- **适应度函数**: $Fitness = \gamma \cdot S_{ru} - (1 - \gamma) \cdot T_{Response} + Diversity\_Bonus$。
  - 平衡了**资源均衡度**（$S_{ru}$）与**响应时延**（$T_{Response}$）。
  - 引入了**节点多样性奖励**，避免过早收敛并减少单点负载。
- **算子优化**: 采用锦标赛选择、单点交叉及基于资源约束的变异算子，确保生成的路径在物理上可行（节点资源充足）。

### 3.2 PLSAFC 流量分类

- **逻辑**: 基于概率潜语义分析（PLSA）和特征词典计算**流膨胀系数 (FEC)**。
- **公式**: $FEC = \frac{w_1 \cdot pkt\_rate + w_2 \cdot regularity}{w_3 \cdot avg\_pkt\_size}$。
- **应用**: 将流量划分为“控制类”（高优先级、确定性需求）和“非控制类”（尽力而为传输）。

### 3.3 PSO 确定性资源编排

- **问题**: 实现论文中的 **RDOTDR**（针对时间确定性需求的资源动态编排）。
- **建模**: 粒子位置代表各节点**软时分 (STD) 时隙**的起始位置。
- **适应度**: 以**最晚完成时间**作为成本函数，通过迭代搜索最小化端到端抖动和时延的预留方案。

### 3.4 软时分 (STD) 时隙管理

- **实现**: 每个节点维护一个 `timeslot_matrix`（时间矩阵）。
- **逻辑**: 模拟真实工业网关对时隙的占用情况，支持寻找连续空闲时隙，确保控制信令的确定性调度。

## 4. 面试高频问题预测 (FAQ)

### Q1: 为什么要同时使用 GA 和 PSO？

**A**: 这体现了分层管控的思想。**GA** 负责在宏观层面选择节点路径（解决“走哪条路”的问题），侧重于长期的资源负载均衡；而 **PSO** 负责在微观层面进行时隙锁定（解决“什么时候走”的问题），侧重于微秒级的确定性调度。

### Q2: 你的模拟器如何保证逻辑与 UI 的分离？

**A**: 我设计了 `EngineCallbacks` 接口类。模拟引擎 `SimulationEngine` 只负责数学计算和状态变更，通过回调触发 UI 层的拓扑刷新、日志记录和动画播放。 这种解耦设计使得算法模块可以轻松脱离 GUI 进行自动化测试。

### Q3: 流量分类算法中的 FEC 公式是如何确定的？

**A**: 该公式参考了项目相关的学术论文。分子部分包含包速率和规律性，属于“扩展集”，其值越高代表控制特征越明显；分母为包大小，属于“收缩集”，工业控制信令通常为小包。 这种设计能极大地拉开不同性质流量的 FEC 分值差距。

### Q4: 如何处理大文件在 Git 中的传输问题？

**A**: 在项目中遇到了 `.exe` 和 `.zip` 文件超过 GitHub 限制的问题。我通过 `git filter-branch` 或 `BFG` 工具清理了 Git 历史中的大文件，并配置了 `.gitignore` 来过滤 `dist/`、`build/`、`.venv/` 和 `.idea/` 等不必要的环境文件。

### Q5: 在高并发请求下，模拟器如何保证不崩溃？

**A**: 系统引入了 QTimer 异步处理机制。在批量请求模拟时，采用 `singleShot` 延迟处理和错峰执行，避免在同一时间点触发大量的 GA 计算导致 GUI 线程阻塞（界面假死）。

## 5. 项目成果展示

- **A/B 测试**: 支持“SIFA 智能模式”与“传统网络模式”的对比。
- **动态监控**: 实时计算用户请求接收率、平均响应时间、RTP（资源-时间乘积）等核心 KPI。
- **场景持久化**: 支持将网络拓扑保存为 JSON 文件，并能完整恢复。
